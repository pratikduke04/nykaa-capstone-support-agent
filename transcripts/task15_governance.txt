PART A - LEAST AUTONOMY: only the Lookup Agent may call check_order_status
##############################################################################

A1. Who holds which tool (design):
  Retrieval Agent      tools = ['rag_lookup']
  Lookup Agent         tools = ['check_order_status']
  Response Composer    tools = none

  Holders of 'check_order_status': ['Lookup Agent']

A2. Enforcement: every agent tries to call check_order_status through the gateway:
  Retrieval Agent      DENIED   -> 'Retrieval Agent' is not allowed to use 'check_order_status'; it holds ['rag_lookup']
  Response Composer    DENIED   -> 'Response Composer' is not allowed to use 'check_order_status'; it holds no tools
  Lookup Agent         ALLOWED  -> tool ran, result: {"found": true, "record_id": "NYK-1005", "status": "Returned", "order_value_inr": 852, "escalat

  Audit log:
    {'agent': 'Retrieval Agent', 'tool': 'check_order_status', 'allowed': False}
    {'agent': 'Response Composer', 'tool': 'check_order_status', 'allowed': False}
    {'agent': 'Lookup Agent', 'tool': 'check_order_status', 'allowed': True}

A3. Evidence from real crew runs (which tools actually executed):
  'What is the return window for apparel?'
    tools executed: ['rag_lookup']   check_order_status ran 0x
  'Where is my order NYK-1005?'
    tools executed: ['rag_lookup', 'check_order_status']   check_order_status ran 1x

WHY this is least autonomy: the agent that reads customer order data is the only one that can; the Retrieval
Agent can only read public policy text, and the Composer has no tools at all, so a prompt-injected or
confused agent cannot reach the order system. The gateway refuses (and logs) any attempt, and a refused
call never executes the tool. The Autogen reviewers have no tools either.
